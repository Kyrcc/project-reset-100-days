# 销售跟进计划生成器

> Project Reset · Day 3 · 制作中

## 业务目标

把 Day 2 的销售线索评分结果继续转换为可执行的跟进任务，避免销售人员只看到 A/B/C 等级，却不知道下一步何时做、做什么、通过什么渠道完成。

## 输入

读取：

`../lead-scoring-assistant/leads_scored.csv`

输入中包含线索编号、公司名称、总分和 A/B/C 等级。

## 跟进规则

规则保存在 `follow_up_rules.csv`，可以用 Excel 修改：

| 等级 | 几天后跟进 | 优先级 | 下一步动作 | 渠道 |
| --- | ---: | --- | --- | --- |
| A | 0 | 高 | 当天联系并预约产品演示 | 电话 |
| B | 3 | 中 | 发送案例并确认具体需求 | 企业微信 |
| C | 7 | 低 | 发送培育内容并观察后续互动 | 企业微信 |

## 计划输出

运行 `follow_up_planner.py` 后生成 `follow_up_plan.csv`，包含：

- `lead_id`
- `company_name`
- `grade`
- `total_score`
- `priority`
- `next_action`
- `channel`
- `due_date`
- `status`

## 运行方法

在当前文件夹中运行：

```powershell
python follow_up_planner.py
```

程序默认使用当天作为计划起算日期。为了复现某一天的结果，也可以指定日期：

```powershell
python follow_up_planner.py --base-date 2026-07-30
```

## 证据边界

- 跟进日期来自人工确认的 A/B/C 规则，不代表客户一定会在该日期回复或成交。
- 当前程序使用自然日，没有排除周末和节假日。
- 跟进动作是示例流程，正式使用前应结合行业、销售周期和团队 SLA 调整。
- 输出状态默认为“待跟进”，不会自动联系客户或发送消息。
